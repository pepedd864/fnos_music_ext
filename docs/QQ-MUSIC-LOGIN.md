# QQ 音乐账号登录

musicdl 音源支持可选的个人 QQ 音乐登录。原有匿名平台仍可使用，网易扫码登录入口保持独立。

## 使用

1. 从已登录的飞牛管理员桌面打开「fnMusic 扩展管理」，选择 musicdl。
2. 在「QQ 音乐账号」选择与会员绑定的登录方式，生成二维码。QQ 方式使用手机 QQ，微信方式使用微信扫码，并在手机端确认。
3. 点击「验证 / 刷新登录」，确认平台接受凭据。仅显示「凭据已保存」时尚未完成在线验证。
4. 在平台列表勾选 `QQMusicClient`，保存配置，再重新搜索歌曲。

二维码三分钟过期；重新生成会作废上一个登录会话。登录持久化在数据卷中，服务重启后仍可读取。登录不会自动更换平台白名单，也不会修改搜索超时。

会员权益、歌曲版权、地区与平台接口共同决定能否返回完整音频和可用音质。扫码成功不表示所有歌曲可播，也不能保证解决网络超时。只请求平台授权的普通完整音频格式，不增加加密音频解密或试听回退。

## 在飞牛音乐中使用

QQ 已改为「先显示歌曲，点击后解析音频」：搜索通过 QQ 资料接口每页取最多 30 首，返回标题、歌手、专辑、封面和时长，不逐首取直链、探活或下载歌词。启用深分页后，飞牛列表继续向后翻页；每页大小固定，默认最多向 QQ 取 10 页。其他 musicdl 平台保留原搜索路径。

点击播放时才为该歌曲批量查询账号可用的普通音质。默认「自动」跟随扩展的音质偏好：高音质依次尝试母带 FLAC、FLAC、320k MP3、128k MP3；平衡从普通 FLAC 开始，先向下再向上；流畅从 128k MP3 向上尝试。搜索结果中的格式和大小是目录信息；实际播放及保存以成功取得的音频为准。显示在搜索列表里不代表账号一定拥有播放权限。没有完整音频权限时返回明确错误，不把失败缓存成「无搜索结果」。

## 音质选择与飞牛 App

在扩展管理页「播放与推荐 → QQ 音乐音质」选择自动、母带优先、无损优先、MP3 320k 或 MP3 128k，对应热重载配置 `FNMUSIC_QQ_QUALITY=auto|master|lossless|mp3_320|mp3_128`。指定档位只向下回落，不擅自升级；128k 没有账号授权的完整音频就报错。保存后下次播放生效，已打开的播放地址保留原档位。

在线歌曲列表按所选档位显示格式、码率及该档的目录文件大小；歌单快照保留各档大小，刷新页面即可随偏好更新，无需重新导入。目录大小不代表已下载或已验证账号权限，实际解析到的回落音质优先。旧快照缺少分档大小时显示未知大小，避免把无损文件的大小标成 MP3；本地曲库文件继续展示真实文件格式。

飞牛手机 App 的「原音质」播放及原文件下载使用上述偏好；「标准」播放固定优先从 QQ 获取 320k MP3（不可用再试 128k），由 ffmpeg 转成飞牛所需的 AAC/HLS；标准下载直接交付 MP3。标准路径不会先拉母带/无损再降码率。扩展的下载音质覆盖设置仍然有效。本地曲库歌曲继续由飞牛处理；网页版目前没有新增播放器内的音质按钮。

在线播放地址带独立的音质身份，URL 解析缓存、音频文件、引用文件与 HLS 会话分档保存。缓存查找不按同名歌曲跨档复用，未记录档位的旧文件保留在曲库，不自动冒充新档位。新保存的 QQ 文件名带 `[QQ-档位]`，其音频标签仍是原歌曲名，可能在曲库里同时存在多个音质版本。

远端播放期间，即使后台边听边存完成，也不切到已嵌封面/标签的本地文件继续做字节定位；下一次播放才使用该档缓存。丢弃重定向地址的客户端在同一登录会话内的非零 Range 请求也会保留起播档位。HLS 起播、分片、心跳和退出统一使用标准档的会话身份，改变原音质偏好不会重置正在播放的标准档会话。

搜索和播放使用独立并发额度及超时，重复播放/拖动复用短期音频链接；刷新链接保持选中的音频格式，Range 字节范围透传。服务重启后可按 QQ 歌曲编号恢复资料和播放，无须先重新搜索。歌词单独按需获取，失败不阻塞播放。账号过期时仍可浏览资料，播放会提示在管理页刷新登录。

此改动改善歌曲搜索和播放；尚未接入完整 QQ 歌手主页、完整专辑目录及个人歌单同步。

## 状态、过期与退出

- 「凭据已保存」表示本机有登录数据；「验证成功」表示最近一次在线验证通过，不代表每首歌曲都有播放权限。
- 「验证 / 刷新登录」会检查账号并在过期时尝试刷新；刷新被平台拒绝时要求重新扫码。网络错误保留原凭据，不报告验证成功。
- 检测到失效的已登录账号时，QQ 播放会提示重新登录；资料浏览可使用匿名接口。退出登录后恢复匿名播放权限。
- 「退出登录」删除本机保存的 QQ 凭据、取消待扫码会话并清理 QQ 歌曲及搜索缓存。它不保证撤销平台端其他设备的登录，请在官方 App 中管理设备授权。
- 此入口暂不同步 QQ 歌单、收藏或推荐，也没有酷我账号登录。

## 存储与接口

默认文件为 `${XDG_DATA_HOME:-/data}/qqmusic/credential.json`，目录权限 `0700`、文件权限 `0600`，采用临时文件和原子替换写入。Docker 对应 `sources-data/qqmusic/`；native 由现有 supervisor 的 `XDG_DATA_HOME` 定位。凭据以明文保存在 NAS 私有目录，具有 NAS 管理权限的人仍能读取；不要分享此目录或其备份。

凭据不写入 `.env`，不由配置、状态或登录检查接口返回，也不输出上游异常正文。管理接口 `/api/qq/auth/{status,login,login/check,verify,logout}` 复用飞牛管理员鉴权；扫码图像和响应禁止缓存。musicdl 内部 `/auth/qq/*` 仅供受信任的同机管理服务调用，保持音源端口绑定 loopback，禁止直接暴露。

只有 QQ 适配器会接收到当前访问凭据（`musicid`、`musickey`、`loginType`），用于平台资料和授权取链；音频 CDN 请求只带普通请求头，不传账号凭据。刷新令牌仅供登录模块使用。账号变更使旧搜索及取链结果失效，避免退出后回填旧账号链接。登录验证和刷新为手动操作，当前版本不后台定时刷新。

Docker 构建和 native 依赖安装均通过 `musicdl-service/requirements.txt` 安装；旧容器仅替换 Python 文件而未安装依赖时，扫码接口会提示更新运行环境。
