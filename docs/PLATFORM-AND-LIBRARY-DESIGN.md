# 音乐平台与 NAS 曲库管理：设计草案

状态：第一批正式实现。React + Ant Design 的 A 布局、平台注册表、QQ 登录/搜索/推荐、宿主目录索引、文件版本、可恢复回收站及持久任务已实现；验证结果见 `CONSOLE-IMPLEMENTATION.md`。酷狗与网易云已迁入统一账号/目录接口；酷我接入公开目录，账号功能仍待后续验证。原生播放器默认版本发布仍待后续接入。

## 已确认的范围

- 平台：QQ 音乐、酷狗音乐、酷我音乐、网易云音乐。
- 曲库：NAS 中由用户选定的音乐目录，包含既有文件和扩展下载的文件。
- 管理：浏览与搜索、启用平台、登录状态、个人推荐、歌曲与文件版本、重复识别、回收站、音质获取、任务状态。
- 界面：按音乐平台和歌曲组织，运行引擎与少用来源放入高级设置。
- 已有 QQ 登录凭据、七个导入歌单及其成员关系在迁移时保留。

## 现状与需要改变的地方

当前 musicdl、网易盒子与洛雪是三个运行引擎，管理页让用户在引擎之间选择。它们不是同一层面的“音乐平台”：QQ、酷狗、酷我属于平台；musicdl 可以承载多个平台。界面与配置需要把这两层分开。

QQ 的登录、目录搜索和音频解析已经有独立实现，推荐也已接入原生漫游。酷狗与酷我可复用 musicdl 的来源实现；当前 NAS 安装的对应来源有 Cookie 处理，但未提供现成扫码登录流程。不能因为实现统一接口，就宣称三个平台都支持同样的登录与推荐能力。

文件目前主要通过缓存、`.ref` 路径引用和歌单快照关联，没有可用于全部目录管理的统一文件目录。WebUI 容器只挂载了仓库和应用数据卷，无法直接看到 NAS 的所有音乐目录。文件扫描与整理应放在宿主侧受限接口，不能靠前端绕过这个限制。

## 1. 平台适配器

先采用内置适配器与注册表。保留后续扩展接口，不先引入运行时任意下载插件的机制。

```text
平台管理 / 搜索 / 推荐 / 下载任务
                  ↓
            平台注册表与调度
           ↙       ↓       ↘
       QQAdapter KugouAdapter KuwoAdapter
           ↓       ↓       ↓
      各平台实现、账号状态与运行引擎
```

每个适配器声明能力，调用方按能力显示操作。相同的界面入口不意味着平台具有相同的能力。

| 操作 | 统一结果 | 差异处理 |
| --- | --- | --- |
| `capabilities()` | 搜索、推荐、歌单、登录方式、可请求音质 | 未实现的能力明确标示，不伪造空结果 |
| `auth_status()` | 未登录、待扫码、待确认、已保存待验证、已验证、已过期、暂时无法验证 | 网络故障与凭据过期分开 |
| `start_login(kind)` / `poll_login(session)` | 二维码、会话期限、扫码状态 | 仅对支持的登录方式开放 |
| `refresh_login()` / `logout()` | 新账号状态 | 登录变更使旧的个人推荐队列失效 |
| `search(query, cursor)` | 歌曲资料与下一页游标 | 搜索不逐首解析音频 |
| `recommend(kind, cursor)` | 推荐资料与下一批游标 | 匿名榜单与个人推荐分开 |
| `playlists()` / `playlist_tracks(id, cursor)` | 平台歌单与稳定成员标识 | 重导入按平台歌单 ID 对账，不另建同名歌单 |
| `resolve(track_id, quality)` | 实际格式、码率、短期音频定位与有效期 | 账号权限或版权不足明确返回；实际音质不只取决于请求值 |

搜索、推荐与播放使用独立的并发限制和总超时。启用状态决定是否参与调度；登录状态独立保留，停用平台不自动退出账号。个人推荐需要有效账号，不能自动退化成匿名榜单。

凭据保存在 NAS 私有目录中。前端只获得脱敏账号、验证时间、状态和可用操作；索引不保存签名音频地址。平台、账号身份和音质共同决定解析缓存的范围。

首批平台交付顺序：QQ 迁入统一接口，酷狗和酷我复用现有搜索/播放实现，再分别验证并补齐账号接入与推荐。只有经过验证的能力才在页面上可操作。

## 2. 把歌曲、平台条目与文件版本分开

“一首歌显示一次”依赖数据模型，隐藏文件名后缀不等于去重。

```text
歌曲记录 Recording
 ├─ 平台条目 ProviderTrack：平台 + 平台歌曲 ID + 对应账号范围
 ├─ 本地文件 MediaFile：路径 + 实际格式 + 码率/采样 + 大小 + 文件状态
 ├─ 默认播放版本：指向一个可用 MediaFile
 └─ 歌单成员关系：指向 Recording，保留原平台条目映射
```

在应用自己的索引中保存这些关系，不修改飞牛官方数据库。建议索引使用 SQLite：扫描、任务、移动和恢复需要可查询的事务记录，不能继续把全部文件关系分散在临时缓存里。

重复判断分成三类：

1. **完全相同的文件**：候选文件经内容校验确认相同，可整理多余副本。硬链接需识别设备与 inode，不能误算可释放空间。
2. **同一录音的多个音质**：合成一个歌曲条目，保留 MP3、FLAC 等文件版本；选择默认播放版本。
3. **疑似相同歌曲**：名称、歌手、时长等相近，只列为待确认。Live、伴奏、重制、不同演唱者不可只凭歌名自动合并。

已有目录的首次扫描只建立索引。全目录内容哈希不应阻塞列表；先采集元数据，再对候选重复文件做后台校验。未知平台来源保持“本地导入”，不能猜成 QQ 歌曲。

## 3. 歌曲与音质管理

### 曲库列表

按歌曲展示名称、歌手、专辑、时长、默认音质、本地文件数、来源和文件状态。支持搜索、按目录筛选、查看多个音质版本、缺失文件和疑似重复。

详情中列出各文件的真实格式、码率、大小和所在目录。文件名里的管理标记不进入歌曲标题。

### 音质操作

- **切换已有版本**：从本地可用文件中设定默认播放版本，不重新下载。
- **重新获取另一种音质**：使用匹配的平台条目与账号，下载到临时位置，校验实际音频后安装新版本。没有可靠平台对应关系的本地歌曲，先搜索并由用户确认正确版本。
- **本地转为较低码率**：单独的转换任务，输出明确标记为转换产物；无法把低码率音频转换为真正的高音质。
- **调整默认音质**：影响之后的解析与获取，不声称已经改变磁盘中的文件。

进行中的播放固定到已选择的文件版本。后台获取与切换默认值不能改变同一播放地址的字节内容或 Range 偏移。

### 文件删除与恢复

默认是把指定文件移入可恢复的回收站，明确区分“移除歌单成员”“移走一个音质版本”“移走整首歌的全部文件”。回收站放在飞牛扫描范围之外，否则文件可能继续显示在飞牛中。

操作记录包含原路径、目标路径、文件身份和恢复状态；发生跨卷复制时需先验证复制结果。路径只允许位于用户授权的目录内，操作前再次确认文件未被外部程序替换。符号链接不能让操作逃出选定目录。

索引、缓存引用与歌单关联在操作后对账。整理结果通过官方支持的扫描或接口反映到飞牛；保留待同步状态和失败重试，不把“文件操作成功”当成“飞牛已经更新”。

## 4. 飞牛音乐能做到什么

扩展管理页可以新增完整的版本选择和文件管理界面。飞牛官方播放器本身没有现成的曲内音质选择控件，新增管理页不会自动让官方播放器出现这个按钮。

若希望飞牛歌曲列表也只显示一次，需要另外选择并验证发布策略：

- 扩展托管的歌曲：向飞牛可扫描目录发布一个默认版本，其余版本放入未扫描的托管目录。
- 已有用户目录：先建立多版本映射，再评估是否通过代理统一呈现、或由用户选择纳入托管；不能扫描后自动搬走文件。
- 官方歌单、收藏、播放历史及旧 GUID 需保持可解析，切换发布版本后验证官方扫描和关联关系。不能只过滤一处列表，否则分页、计数与歌单成员会不一致。

这部分必须单独验证原生网页与手机 App 的行为，不能把管理页去重直接当成飞牛原生列表已经去重。

## 5. 新界面

用户已选择 Ant Design 组件库。前端按 React + Ant Design 实现，现有交互原型的 A/B/C 三种布局已迁移为真实组件；运行时资源本地打包。

推荐 A 版：**曲库优先**。主导航为我的曲库、音乐平台、下载任务、音乐目录，整理入口为多音质版本与回收站。

音乐平台页直接展示 QQ、酷狗、酷我，卡片上有启用状态、登录状态和实际支持的能力。网易、洛雪和其他来源默认折叠在“其他来源与高级接入”。运行引擎、并发和细节配置不占据日常界面。

另有两个可切换布局供对照：B 版平台工作台以账号和来源为中心；C 版三栏工作区同时展示歌曲、录音信息与各音质文件。

原型是内存交互示例，不连接 NAS、不触发真实登录、下载或文件操作。不能直接当作生产页面部署。

## 6. 实施批次与验收

| 批次 | 交付 | 验收重点 |
| --- | --- | --- |
| 1. 平台统一 | 注册表、QQ 完整迁移、酷狗/酷我适配、启用和账号能力页面 | QQ 原有搜歌/漫游/播放不退化，单平台故障不拖累其他平台，能力状态真实 |
| 2. 全目录曲库 | 宿主扫描、独立索引、歌曲与文件详情、重复候选 | 指定范围全部可见、增量扫描、版本识别、目录范围校验、保留既有文件 |
| 3. 管理操作 | 回收站/恢复、默认版本、重新获取与转换任务 | 可恢复、失败不中断已有文件、音频与字节范围正确、当前播放不中断 |
| 4. 飞牛同步 | 默认版本发布、扫描对账、歌单与旧标识兼容 | 原生列表计数/分页/歌单一致，无重复导入，网页及手机实测 |

每批交付实际可用的纵向功能，不等所有平台功能齐全后才验证。正式改造前保留应用数据与索引迁移的回退路径。
